# 部件分类法（Part Taxonomy）

本文件定义「什么算一个部件」以及 12 组功能槽位。目标不是给出一张漂亮的清单，而是让拆解结果**可替换、可验证、可计量**——架构改进可以替换算子，也可以改变连接拓扑、约束或共享状态。

---

> 槽位号与组名以 `references/ontology.md`（由 `ontology.json` 生成）为准。
> 本文件只负责判断方法：什么算一个部件、怎么找证据、常见误标。
> 如果这里的槽位号与 ontology.md 冲突，以 ontology.md 为准并且去修 ontology.json。

## 0. 部件、接口与替换

部件可以是计算节点，也可以是绑定在计算节点上的结构属性或计量项。先定位它的输入、输出、作用范围和证据，再选择研究粒度。

- **接口兼容**：输入输出对象、轴、形状、dtype、单位、测度和状态约定可接入上下游。接口相同不能证明行为相同，例如 f(x)=x 与 g(x)=2x 都是 R→R。
- **行为等价**：在明确输入域、参数对应与条件下，两个计算给出同一结果。必须记录推导 claim 和成立条件；检查器只检查证据指针，不能代替数学证明。
- **实现等价**：同一数学计算的实现重排或数值实现变化。必须说明精度、误差容限和硬件假设，不能只凭形状判定。
- **联动替换**：多个节点需同时变化时，写入 coupled_replacements；若修改共享参数，列出共享参数组及其全部使用者。联动并不意味着这些节点是同一个部件。

Encoder 可以作为复合部件；若研究靶点在其内部，则继续展开。按研究目标决定粒度，不因模块大或接口重复自动合并。

### 终止规则

默认先按组→槽位→子槽位拆解；在当前问题下没有新的可检验差异时停止。只有在给出计算等价依据后，才能将两个描述合并为同一计算的不同表述。缺少细节时记录 missing，不把“没有证据”当成“等价”。停止理由写入 granularity_note。

## 1. 分开记录重要性依据

| 字段 | 记录什么 | 不能推出什么 |
|---|---|---|
| importance.claimed_centrality | 作者在摘要、正文或图中强调的角色及 claim_ids | 不能直接推出因果必要性 |
| importance.theoretical_dependency | 某结论对部件的依赖及 claim_ids | 不自动代表实验贡献大小 |
| importance.ablation_ids | 已登记消融比较 | 预算、数据、调参与重训条件不明时不能声称受控比较 |
| importance.interaction_ids | 单独与联合干预的差异 | 联合影响不能直接归因于某一个节点 |
| cost_dominant | 在声明规模和计算约定下的成本主项 | 不代表其他部件没有研究价值 |

无消融时可合法保留 unknown。load_bearing 仅作为旧产物的历史字段，不再参与准入。以稳定性、可辨识性或可靠性等目标提出改进时，也必须给出可测指标、贡献依据和否定条件。

图结构与消融的完整字段及边界见 `architecture-contract.md`。

## 2. 十二组槽位

每组的格式：**问的问题 / I/O 契约 / 证据要求 / 常见误标**。

### R. 输入与表示（R）——  网络看到的最小单元是什么，什么信息在这一步被销毁

| 槽 | 问题 | I/O 契约 | 证据要求 |
|---|---|---|---|
| R1 离散化单元 | token / patch / node / collocation point / 像素？ | 原始数据 → 单元序列或集合 | 必须引原文对单元的定义；分块大小、采样率属此槽 |
| R2 提升算子 | 离散单元 → d 维向量怎么做的 | 索引或局部块 → R^d | embedding 矩阵、patchify 卷积核、线性 lift |
| R3 连续坐标编码 | 连续坐标（时间、空间、参数）如何进入网络 | R^k → R^m | Fourier features、RBF、正弦编码、归一化坐标 |
| R4 输入标度 | 是否逐通道/逐域归一化 | R^d → R^d | 输入侧 normalization、domain scaling |
| R5 条件注入点 | 保真度、边界条件、物性参数从哪一层进 | 条件向量 → 影响后续所有层 | **多保真与物理约束的关键槽**；注明是拼接、FiLM、超网络还是 cross-attention |
| R6 掩码与分组 | padding / sensor / multi-query 分组结构 | 布尔掩码 → 影响聚合 | 掩码语义与其在各层的传播方式 |

**常见误标**：把「位置编码」同时算进 R3 与 G1。规则：**进入方式**算 R3，**编码形式与其外推性质**算 G1，同一事实只在一处标 F，另一处写交叉引用。

### P. 先验载体（P）——  哪些结构是硬约束，哪些只是软偏好

| 槽 | 问题 | I/O 契约 | 证据要求 |
|---|---|---|---|
| P1 局部性 | 感受野由什么界定 | 邻域索引 → 聚合范围 | 卷积核尺寸、window、stencil、邻居跳数 |
| P2 对称群 | 断言了哪个群的等变/不变性 | 群作用 → 输出变换规律 | **必须写出群**（平移/旋转/置换/规范）；区分硬编码与学出来 |
| P3 关系结构 | 图、拉普拉斯、注意力掩码、边界算子 | 邻接或算子 → 混合权重 | 关系是数据给定还是学习得到 |
| P4 多尺度 | 是否分层、金字塔、小波、多重网格 | 分辨率层级 → 跨层传递 | 池化/上采样位置与倍率 |
| P5 几何与流形 | 数据在网格、流形、点云还是规则域 | 坐标+度量 → 算子 | 度量是否显式使用 |
| P6 因果性 | 是否强制单向依赖 | 时间索引 → 可见集 | causal mask、自回归约束 |

**常见误标**：把「用了 attention mask」写成 P2 等变性。掩码是对称性的一种实现手段，只有当它对应某个群作用时才升格为 P2。

### B. 主干与组合（B）——  深度方向如何串联，状态如何跨步传递

| 槽 | 问题 | I/O 契约 | 证据要求 |
|---|---|---|---|
| B1 块拓扑 | 残差/稠密/并行分支，norm 在支路内外 | R^d → R^d | 画出块的精确数据流，标出 norm 位置 |
| B2 深度宽度调度 | 各层宽度、是否跨层共享权重 | 层索引 → 参数集 | 权重共享 = 隐式循环，必须注明 |
| B3 跨块信息流 | skip、门控、早退、超连接 | 多块输出 → 单块输入 | 门控的输入是什么 |
| B4 递归/状态机制 | 有没有显式状态：RNN hidden、KV cache、SSM state、memory token | 状态 → 新状态 | 状态维度与更新式；这是长上下文与流式的分水岭 |
| B5 并行结构 | 序列化 scan、块并行、树形归约 | 序列 → 并行分解 | 影响延迟与显存，不是纯实现细节 |

### M. 混合算子（M）——  信息在位置之间如何交换（含 attention 与一切替代品）

| 槽 | 问题 | I/O 契约 | 证据要求 |
|---|---|---|---|
| M1 交互范围 | 全对全 / 局部 / 稀疏 / 全局 token | N×N 或 N×k 的可见集 | 复杂度随 N 的阶 |
| M2 打分-聚合形式 | 具体代数形式 | Q,K,V → R^{N×d} | 写出式子：softmax、核特征映射、门控线性、卷积、加权和 |
| M3 路由与选择 | top-k、MoE、硬注意力、检索 | 打分 → 选择集 + 权重 | 路由是否可微、负载均衡怎么做 |
| M4 多头与分组 | 头数、共享方式、头间交互 | 多头输出 → 合并 | GQA/MQA/MLA 属此槽 |
| M5 条件化路径 | 除了自混合，还混合什么 | 上下文/参数/物理状态 → 混合 | cross-attention 的对象必须写明 |
| M6 状态更新规则 | 对 SSM/线性注意力：A,B,C,Δ 如何离散化 | 状态 → 状态 | 必须给离散化方式（ZOH/bilinear/Euler） |

**判定口诀**：问「它能否写成一次线性扫描」——能，则属于状态型（M6/B4）；不能，需要成对交互，则属于 M1 的全对全家族。

### E. 通道变换（E）——  每个位置上特征如何被重写

| 槽 | 问题 | 证据要求 |
|---|---|---|
| E1 逐点变换 | MLP、单线性、门控 MLP | 层数与隐宽 |
| E2 扩张比与瓶颈 | FFN 扩张比、低秩分解 | 具体倍数与秩 |
| E3 激活函数 | 形式与其光滑性/频谱性质 | **对 PDE 类任务，激活的光滑性直接决定能求几阶导** |
| E4 乘性调制 | FiLM、scale-shift、门控 | 调制信号来自哪里 |

### N. 归一化与数值（N）——  统计量沿哪些轴取，数值如何不炸

| 槽 | 问题 | 证据要求 |
|---|---|---|
| N1 归一化类型与轴 | LayerNorm/RMSNorm/BatchNorm/GroupNorm | 沿哪些轴求统计量（这决定了它对 batch 的依赖） |
| N2 位置 | pre/post/sandwich、QK-norm | 与残差支路的相对位置 |
| N3 仿射与条件化 | 是否可学习 γ/β，是否由输入产生 | 条件化参数来源 |
| N4 数值稳定 | eps、fp32 upcast、logit cap、残差缩放、初始化缩放 | 缺失时标 M，不要猜 |

### G. 位置与序（G）——  顺序信息如何编码，能否外推

| 槽 | 问题 | 证据要求 |
|---|---|---|
| G1 编码形式 | 绝对/相对/旋转/学习/无 | RoPE 属此 |
| G2 基函数 | 正弦、Fourier、随机特征 | 频率范围与是否可学习 |
| G3 外推机制 | NTK-aware、ALiBi、长度课程 | 论文是否声称外推，有无实验 |
| G4 非序列位置的定位 | 网格索引、坐标、拓扑序 | 连续域任务常被漏掉 |

### O. 读出与解码（O）——  输出如何被聚合与生成

| 槽 | 问题 | 证据要求 |
|---|---|---|
| O1 聚合读出 | CLS/均值/末位/注意力池化/算子基系数 | 池化发生在哪个轴 |
| O2 解码方式 | 自回归/并行/扩散/流匹配/直接回归 | 与训练目标是否一致 |
| O3 输出参数化 | logits、均值方差、分布、场值、基系数 | 是否输出不确定性 |
| O4 约束投影 | 对称性、守恒、边界条件的硬编码 | 区分「软惩罚」与「硬投影」——这两者性质完全不同 |

### L. 目标函数（L）——  每一项在拉扯什么

| 槽 | 问题 | 证据要求 |
|---|---|---|
| L1 主损失 | 函数形式与定义域 | 写出式子 |
| L2 辅助与正则 | 负载均衡、熵、平滑、谱正则 | 系数值（若无则标 M） |
| L3 物理与一致性 | PDE 残差、守恒、无散度 | 残差如何采样与加权 |
| L4 权重平衡 | 固定 λ、不确定性加权、GradNorm、自适应 | **λ 数值常缺失，必须标 M 而不是编一个** |
| L5 采样与课程 | 配点分布、LHS、重要性采样、数据混比 | 点数与分布 |
| L6 保真度结构 | 多保真如何组合：线性 ρ·f_L+δ、非线性、层级 | 相关系数是否可学习 |

**判定口诀**：对每一项写下「它把梯度推向哪个方向，与哪一项竞争」。写不出来说明你还没理解这项损失。

### T. 训练与优化（T）——  常被省略但影响架构可行性

| 槽 | 问题 |
|---|---|
| T1 优化器与调度 | Adam/AdamW/SGD，warmup，衰减步长 |
| T2 精度与并行 | bf16/fp8、TP/PP/EP、切分方式 |
| T3 初始化与稳定性 | 初始化缩放、梯度裁剪 |
| T4 有效 batch 与序列长度 | 与架构设计强耦合（如注意力 softmax 的温度） |

**注意**：J 组经常「论文没写」。此时不要从开源代码反推成论文事实——见 §4 的证据分级。

### I. 推理路径（I）——  部署时的行为可能与训练时不同

| 槽 | 问题 |
|---|---|
| I1 单次 vs 自回归；缓存策略 | 是否维护跨步状态 |
| I2 测试时计算 | 采样、CoT、搜索、迭代精化 |
| I3 近似 | 量化、稀疏、蒸馏、剪枝 |
| I4 单位成本 | 每 token / 每 query 的 FLOPs、字节、延迟 |

### S. 规模计量（S，派生层）——  这一层不是抄来的，是算出来的

| 槽 | 要产出什么 |
|---|---|
| S1 参数分解 | 每个部件的参数量，谁占主导 |
| S2 FLOPs 分解 | 写成 N（序列/点数）、D（宽度）、P（参数量）的函数，标出主项阶数 |
| S3 状态与显存 | KV cache / SSM state / 激活值，按 token 或按样本计 |
| S4 通信与带宽 | 并行下的 collective 量级（粗算即可） |

**S 组是改进方案的锚点**。没有 S2，任何「更高效」的改进都无法被证伪。

## 3. 一篇一架构的选取规则

论文常提出一个家族。只提取**一个**核心架构，选取顺序：

1. 摘要主句点名的那个；
2. Fig.1 / 系统图里画的那个；
3. 主结果表（不是消融表）里的最终模型；
4. 若有多个规模变体（Tiny/Base/Large），取被用来支撑主张的那一档，并在 `variants` 里列出其它档。

**不要**把家族平均成一个「典型配置」，也不要为了完整性把每个消融变体都拆一遍——那会把论文的主张稀释掉。变体只记「改动了哪个槽位」，不重复拆解。

## 4. 证据分级（每个部件必带一个）

| 标记 | 含义 | 必填字段 | 允许的写法 |
|---|---|---|---|
| `F` | 论文事实 | `evidence.loc` + 顶层 `claim_ids` | 页码+节号、公式号、表号、图号。例 `p7 §3.2`、`eq(4)`、`Tab.2` |
| `U` | 上游论文补齐 | `evidence.ref` + 顶层 `claim_ids` | 可解析标识：arXiv id / DOI / OpenAlex id |
| `D` | 自己的推导 | `evidence.derivation` + 顶层 `claim_ids` | 必须写出实际代数步骤，不能只写「可以推出」 |
| `M` | 检索后仍缺失 | `search_record` | 记录查询串、端点、结果数、失败原因、替代思路 |

**硬规则**：

- 没有标记的部件行 = 无效行，检查器会报错。
- 任何数值（层数、维度、λ、学习率）必须带 `F` 或 `U`。标 `D` 的数值只能是推导出的复杂度阶或量级，不能是「大概 12 层」这种猜测。
- `M` 不等于失败。`M` 是诚实的高价值信息：它精确指出了论文的可复现性缺口。但 `M` 必须附检索记录，否则等于没查。
- 同一事实只有一个 `F` 锚点，其它位置写 `see <part_id>`。

## 5. 机器可读骨架

完整字段定义以 `../ontology.json` 和生成的 `../assets/anatomy.schema.json` 为准。
从 `../assets/anatomy.skeleton.json` 创建草稿，完整合成回归示例见 `../assets/anatomy.fixture.json`。
这里不再维护第二份内嵌 JSON 示例。

v2 中 `parts[].slot` 是 R1/M2 等槽位 ID；`parts[].claim_ids` 在部件顶层；
`claims[].subject` 精确指向部件 ID；`sources[]` 登记来源，`paper.source_id` 登记主论文。
F/U/D 的标签同时受到类型、subject 和来源关系检查。M 项允许 claim_ids 为空，但必须保留检索记录。
具体命令、迁移和发布边界见 `validation-workflow.md`。

## 6. 自检问题（写完部件表后逐条回答）

1. 哪些部件被作者强调、被理论依赖或有消融证据？三种依据是否被分开记录？
2. 哪个部件是 cost-dominant？把它写成 N、D、P 的函数后，主项阶数是多少？
3. 相同接口下是否存在不同计算？是否有明确的等价推导，而非只比较形状？
4. 有没有哪个部件我说不清「换掉它会破坏什么」？如果有，说明还没拆到位。
5. 部件表里有多少行是 `M`？如果超过 30%，说明论文信息不足或检索不够，需要在报告里显式声明可信度上限。
