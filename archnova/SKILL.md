# ArchNova

默认由当前 Agent 完成阅读、推理、设计和审查。复制本目录到 Agent 的 skills 目录即可使用；无需先安装 Python、jsonschema、PyTorch/JAX 或配置额外模型 API。

## 默认工作方式（优先于参考文档中的工具命令）

- 使用宿主 Agent 已有的文件读取、代码检索、联网搜索和图像阅读能力。工具或网络不可用时说明具体证据缺口，继续完成不依赖它们的分析与设计。
- 不为加载技能、生成架构设计、总结模型或提出训练策略而运行 pip、安装框架、调用 CLI、生成调度状态文件或要求 API key。
- JSON schema、ontology 和组件库是可直接阅读的设计规范；人工式合同核对与机器 schema 校验分别标记。未运行脚本时写“机械校验未执行”，不能写“校验通过”。
- Python 脚本是可选辅助工具，仅在确实需要机械校验、可执行原型、训练、计时、回放或打包时使用。先检查现有环境；缺依赖时只将该执行项标记 unavailable，不中断设计流程，不自动安装依赖。
- 用户要求真实训练、GPU 测量或正式机器发布门时，必须取得实际运行收据。缺环境可以交付设计与实验计划，不能交付虚构结果。

## 1. 确定任务与证据

识别 paper-only、code-only、paper-and-code 或从需求出发的设计任务。整理目标、输入输出、数据模态、精度/延迟/显存预算、训练条件、部署环境与约束；未提供条件写“待补充”，不编造。

直接阅读论文、源码、配置、公式和架构图。区分来源事实、源码观察、推导、设计假设与未知项；每个关键事实附文件/行号或论文页码/公式位置。有工具时固定快照与哈希；无法计算时明确未固定，不能杜撰。

## 2. 总结所用模型的特点与不足

恢复统一计算图，包括层/算子、张量形状与轴、参数共享、信息/梯度路径、训练/推理分支及状态更新。

区分网络本体、推理状态、训练状态、前置处理和分布式切分视图。覆盖 MLP、CNN、Transformer、RNN、状态空间、扩散、GNN、神经算子、多模态和混合结构。

逐项报告模型特点、适用条件、不足假设及诊断依据。没有归一化、残差或某类算子不自动意味着缺陷；必须结合深度、任务、数值与梯度证据解释风险。结构诊断不能替代实测。

## 3. 按功能探索组件与架构

任务类型仅作为先验，不限制组件来源。按局部性、长程依赖、状态记忆、频域/物理约束、路由、几何关系、跨模态对齐、稳定优化或部署效率检索和组合组件。

- 对照简单基线，定位具体瓶颈，提出结构不同的候选，避免换名式创新。
- 对跨域借用写清对象映射、保留的不变量、源保证依赖与新失效边界。
- 检查输入输出形状、dtype/layout、感受野、序列长度、注意力头数、跳连位置、共享参数、状态生命周期与资源代价。
- 给出网络定义、逐层说明、数据流图和明确连接；未定的接口保持未知，不能用组件名称列表冒充完整计算图。
- 参数量只对已完全定义结构给出精确值；其余给出公式、假设和估算范围。启发式新颖性排序不代表科学突破。

## 4. 自主探索训练策略与微观设计

结合模型和任务提出学习率/调度、优化器、初始化、深宽、残差/门控、归一化轴与 epsilon、激活、正则化、损失、数据增强、课程、采样、精度和状态管理等候选策略。

每项绑定具体节点或瓶颈，说明机制、适用条件、改动、预期收益、代价、失败条件及消融。先以小预算筛选；一次控制有限变量，用失败证据修订假设。没有真实梯度或训练曲线时不宣称策略有效。

## 5. 可信度验证与交付

将设计判断、有限样本验证、实测性能和一般性论证分开：

- 固定基线、指标、数据拆分、预算、种子、比较条件和否定标准。
- 计划形状/接口检查、数值/梯度核对、消融、反例、重复实验、留出/OOD 与部署测试。
- 不使用留出结果继续选结构；不凭 passed 布尔值、自评分数、空收据或论文摘要晋级为可信事实。
- 只有实际证据支持的具体结论可称已验证；没有证据时交付提案、缺口和下一实验。

默认交付：模型画像与不足、候选网络定义、逐层说明、参数与成本分析、数据流图、训练策略、微观改造、基准测试计划/真实结果、部署要求以及证据与未决问题。按任务规模组织，不机械填无关栏目。
