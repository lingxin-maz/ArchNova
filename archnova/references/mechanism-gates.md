# 机制性准入门

组合泛化是硬性准入条件。候选必须在重组、置换或新组合探针上与参数匹配基线比较；标准任务提升而组合探针没有结构性增益时，候选保持 blocked。

实现前需要异构评审共识。共识门要求足够数量的独立评审者、独立身份和一致 verdict；它过滤先验偏见，但不替代静态验证、训练或硬件实测。

可靠性敏感场景可以要求可逆/忠实证书。候选必须声明可逆原语或可逆包装，并提供反向执行、重构误差和贡献可加性收据。缺失证书时状态是 unresolved 或 blocked，不能由解释文字代替。

安全 harness 随候选结构和部署领域重新生成，并要经过对抗审查与效用/安全权衡测量。固定的全局安全规则不能作为新拓扑的充分证据。

条件权重生成只用于降低筛选成本。使用前必须完成排列/缩放规范化、检查点兼容性和函数等价性检查；它不能替代完整训练，也不能把未对齐的权重数值直接比较。

`mechanism_gates.py` 输出每个门的状态以及 `mechanism_admission`。任何 blocked 门阻止晋升； unresolved 或 planned 只能保留为设计候选。
